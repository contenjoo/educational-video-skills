# 実際の失敗から得た制作時の確認事項

[한국어](production-checks.md) · [English](production-checks.en.md) · 日本語

制作と対話で起きた失敗を、今回の判断と検査に適用する。非公開アカウント、個人用音声・パス、原講座は必要としない。

| 失敗 | 今回の対処 | 自動検査の限界 |
| --- | --- | --- |
| 既存プロジェクトの方式を取り違える | 実際のREADME、入力、レンダリングコマンドを読み、方式と成果物を一文で示す。製品名だけで編集方式を決めない | 方式は依頼と実素材で決まる |
| 簡単な見本だけで大量制作の時間を見積もる | 短い完成授業と、メニュー・権限・複数操作を含む代表場面を仕上げ、必要な修正後に承認済みの一括作業を続ける | 単一のレンダリング時間は、撮影・音声・確認・公開の総時間ではない |
| 空の番号枠、対象の横や消えた操作への強調 | 原本とオーバーレイを分け、クリック前と結果を保全する。説明する時点の実対象に番号のない四角を付け、番号削除後に余白と配置を直す | 座標とSHAだけでは意味上の対象が正しいか判断できない |
| 縦の切り抜きでメニューが消え、説明が重なる | 異なる強調状態と遷移を実出力サイズで確認し、拡大・マスキングで必要な操作や文脈を隠さない | 数枚の抽出確認は全状態の確認ではない |
| 動画だけ翻訳し、資料・メニュー・フォルダーを残す | 動画、SRT、表示・読み上げ台本、資料、フォルダー、実際のメニュー文言を言語別の納品物として扱う | フォントの存在は文字描画、改行、RTLの整形・順序の保証ではない |
| 同じ音声を保ったまま元の不具合を見逃す | 短い音声見本と、元音声・最終MP4の抜け、繰り返し、切れ、無音、発音を確認する。長い生成は扱える場面・バッチに分け、再試行前に既存結果を調べる | ハッシュ一致、信号・文字起こし・音量検査は自然な発音や全編聴取ではない |
| 発話中の不自然な間や長さゼロで消える字幕 | 尺合わせのため発話を切ったり速度を変えたりしない。必要な間は実測無音や文末に入れ、表示台本の全文と最終字幕・時刻を照合する | 推定時刻は強制アラインメントではない |
| 講座名・本数・次回予告の不一致 | 確定した一つのカリキュラムから表紙・導入・まとめ・次回予告を作り、発話の意味と実画面を照合する | 正常な動画でも誤った内容を教え得る |
| Unicode名の不一致やFFmpegが一括入力を消費 | 原名を保ちながら比較時にNFC正規化し、一括処理ではFFmpegの `-nostdin` とsubprocessのDEVNULLを使う | 名前の一致は内容やアップロード・再生を証明しない |
| 認証・モデル・ネットワーク・環境の問題をスキルの問題と混同 | 推論、アカウント、Python/Pillow、npm接続、TTS、レンダリングを切り分け、通常の承認手順を使う。全体設定や保護を黙って変えない | 正常終了だけでは使用可能な映像を証明できない |
| ローカル修正やアップロードを学習者向け版と混同 | 依頼された各公開先でID・URL・進捗を保ち、差し替え結果と対象講座・統合サイト・Drive・モバイルの再生を確認する。旧素材の廃止は依頼範囲で差し替え確認後に行う | 再エンコード後はハッシュが違う場合がある。ローカルSHAと配信先の素材ID・版・長さ・修正場面を記録する |
| 書類と再検査が制作を圧迫 | 既存の入力・レンダリング・確認記録に必要な事実だけ追加し、共有ツールを再利用する。関連変更や新しい問題があるときだけ再検査する | 不要な授業別スクリプト、証拠の重複、相互承認を増やさない |

## 最終ファイルの検査

両スキルに同梱の `scripts/check_media.py` はPython標準ライブラリーとFFmpeg/FFprobeを使う。

```bash
python3 "$SKILL_DIR/scripts/check_media.py" output/lesson.mp4 --srt output/lesson.srt --expected-text output/narration.txt --output qa/media.json
```

`--expected-text` は見出し、授業番号、時刻、Markdownを除いた**承認済み表示台本の全文**である。発音用と異なる場合は字幕に表示する表記を使う。見出し付き台本から実際の読み上げ部分を抽出する。キャプチャ用レンダラーはこのファイルを出力し、同じ検査を実行するため、未変更の結果を再検査しない。Remotionでは既存プロジェクトのMP4・SRT・承認済み台本を使う。

全編デコード、映像・音声ストリーム、有効な長さ、実質的に空の音声、字幕の欠落・繰り返し・重複・長さゼロ・範囲外を検査する。長い行や時間間隔は**警告**として言語と配置を確認し、必要なら `--max-line-chars` を調整する。成功でも状態は `technical_checks_passed_pending_review` である。発音、画面と発話の意味の一致、人による全編聴取、公開版確認を自動合格にしない。

## 結果の報告

素材と提供された中間ファイル、実コマンド、最終SHA、検査・警告、再生した範囲、未実施項目、公開先ごとの状態を既存の完了報告にまとめる。ローカル制作、アップロード、差し替え、公開再生を区別する。補助を受けた作業を独立した全工程の成功と扱わない。撮影・音声・レンダリング・確認・公開の時間と外部待機を分け、不確実な時間を保証しない。

利用者からの症状、ローカルで再現した不具合、記録された修正、確認済み公開版を分ける。実ログ・ファイルの前に原因を断定しない。未解決の警告は品質確認完了ではなく、許容した警告には実際に確認した理由を残す。
