# 첫 실행에서 막히는 지점

[English](first-run.en.md) · 한국어

- `No module named PIL`: 렌더를 실행하는 같은 Python에 Pillow를 설치한다. 가상환경을 썼으면 해당 Python 경로로 실행한다.
- `ffmpeg`/`ffprobe` 없음: 시스템 패키지 관리자로 설치하고 PATH를 확인한다. Node.js는 이 방식에 필요하지 않다.
- 폰트 오류·네모 글자: 실제 한국어 글리프가 있는 폰트 파일을 지정하고 `--frames` 결과를 눈으로 확인한다.
- 검수 SHA 불일치: 이미지·음성이 바뀐 것이다. 원인을 확인하고 실제 수정본을 검수한 후 기록을 갱신한다. 검사 코드를 제거하지 않는다.
- 시스템 음성 생성이 성공 코드인데 소리가 없음: macOS의 제한된 실행 환경에서는 빈 파일이 생길 수 있다. ffprobe로 실제 길이와 음성 스트림을 확인한다. 필요한 정상 권한만 승인받거나 사용자 녹음을 사용한다.
- Claude/Codex CLI 인증이나 모델 오류: 해당 호스트에서 로그인·지원 모델을 확인한다. 사용자 전역 모델·보안 설정을 임의 변경하지 않는다.
- 연결 도구 계정과 브라우저 로그인 계정이 다름: 캡처 출처 계정을 먼저 확인한다. 이 스킬은 제품 타임라인 편집이나 미디어 업로드가 필요하지 않다.
- 긴 텍스트가 화면에 맞지 않음: 장면을 나누고 요약 caption을 짧게 한다. narration은 별도 자막·대본으로 보존한다.

## 브라우저 URL 확인 단계에서 녹화가 시작되지 않을 때

- 창 제목을 읽었어도 현재 URL을 검증하지 못했다면 `녹화 시작 전 차단 / Remotion 렌더 미시도`로 보고한다. 브라우저 도구의 실패만으로 Remotion이 지원되지 않는다고 결론 내리지 않는다. 정확한 내부 원인은 진단 로그 없이는 확정하지 않는다.
- URL 신뢰 확인을 우회하거나 보안 설정을 끄지 않는다. 같은 오류가 반복되면 자동 녹화를 중단한다. 창 재열기·탭 하나만 남기기·앱 업데이트를 근거 없이 반복 요청하지 않는다. 원인이 달라졌다는 진단 근거가 있을 때만 재시도한다.
- 기존 녹화 파일이 제공되면 브라우저 제어 없이 길이·영상 스트림·필요한 실제 조작·개인정보를 확인하고 편집을 이어간다. Chrome이나 특정 사이트가 열려 있어야 파일을 편집할 수 있는 것은 아니다. 파일이 없다면 필요한 동작을 짧게 직접 녹화해 달라고 안내하고, 확보 전에는 녹화 완료로 보고하지 않는다.
- 사용자가 무음·자막 영상을 요청했다면 TTS 생성이나 음성 제공을 필수로 요구하지 않는다. Remotion 결과물은 `python scripts/check_media.py lesson.mp4 --silent --srt lesson.srt --expected-text captions.txt`로 검사한다. `captions.txt`는 승인된 전체 표시 문구다. 이 옵션은 음성이 있는 영상의 음성 검사를 생략하는 용도가 아니다. 캡처 전용 `render_lesson.py`는 여전히 내레이션 입력을 요구하므로 무음 제작 지원으로 오인하지 않는다.
- 도구 복구를 요청받으면 제품·도구 버전, 오류 원문, 녹화 시작 여부를 확인한다. 다른 컴퓨터에서 성공한 테스트를 해당 Windows 환경 복구의 증거로 쓰지 않는다.
