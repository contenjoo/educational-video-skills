# 캡처 교육영상 만들기

실제 화면 → 화면 확인 후 대본 확정 → 장면별 음성 → Pillow 화면 카드 → FFmpeg 인코딩 → 재생 검수 순서로 제작한다. 기존 교육영상 제작 프로젝트의 공통 절차를 독립 실행형으로 옮겼다. 기존 프로젝트의 1,000줄 렌더 어댑터나 강의별 규칙을 그대로 복제한 것은 아니다. 동봉 Python 렌더러로 로컬에서 제작한다.

[English instructions](SKILL.en.md) · 한국어

## 반복 오류를 줄이는 순서

기존 프로젝트를 지칭하면 실제 제작 도구·입력부터 확인한다. `계획·대본 → 실제 화면 확인과 대본 보정 → 음성 → 짧은 완성본과 복잡한 대표 장면 → 일괄 제작 → 최종 검수 → 요청된 목적지 확인`으로 진행한다. 설명과 다른 화면, 틀린 마킹, 자연스럽지 않은 음성은 대량 제작 전에 고친다. 이는 중간마다 사용자 승인을 다시 받으라는 뜻이 아니다.

실행 전 [재발 방지 기준](references/production-checks.md)을 읽고 관련 항목만 적용한다. 클릭 전후 상태와 설명 시점의 표시, 문구·음성·목차의 일치, 언어별 납품물, 실제 게시 버전을 확인한다. 이미 통과한 검사를 이유 없이 반복하거나 검수 서류를 늘리지 않는다. 동봉 `scripts/check_media.py`로 완성 파일·SRT·승인된 표시 대본을 대조하고, 자동 검사로 확정할 수 없는 항목은 미확인으로 남긴다.

## 시작

- 학습 대상·완성 과업·분량·언어·화면 자료를 확인한다. 실제 화면에서 확인한 기능만 설명하고 사용자의 기존 자료를 보존한다.
- Python 3.9+, Pillow, FFmpeg/FFprobe, 한국어를 지원하는 폰트 파일이 필요하다. `scripts/preflight.py --mode canva`로 검사한다. 정확한 실행법과 입력 규약은 [references/capture-workflow.md](references/capture-workflow.md)를 읽는다.
- 실행 가능한 터미널이 없는 앱은 제작 준비까지 가능하다. 파일을 렌더하지 않았는데 완성됐다고 말하지 않는다. 어느 제품의 특정 MCP 이름·개인 경로·목소리에도 의존하지 않는다.

## 실제 화면과 대본

1. 사용자 제공 실제 캡처·녹화 또는 지원되는 브라우저 도구로 자료를 확보한다. 녹화에서 추출한 프레임도 원본 구간을 기록한다. 정지 이미지를 이어 붙인 영상은 캡처 기반 영상이라고 표시한다.
2. 개인정보를 가리고 필요한 조작 영역을 확대한다. 클릭 위치는 숫자 없는 네모 테두리로 표시한다. 가려진 메뉴·실패한 조작·줄바꿈을 성공한 결과로 설명하지 않는다.
3. 이미지를 직접 눈으로 확인한 뒤에만 `image_review`를 승인하고 해당 파일 SHA-256를 기록한다. 가상의 검수 담당·시각·캡처 증거를 만들지 않는다.
4. 짧은 해요체로 한 장면에 한 과업을 설명한다. 확인 문제·실습 시간·결과 확인을 넣는다. 불필요한 제작 설명이나 JooShow 등 제작 도구의 잔여 표기를 학습 화면에 남기지 않는다.

## 음성과 렌더

- 본인 녹음 또는 선택한 TTS를 사용한다. ElevenLabs를 선택한 경우 실제 사용 가능한 모델·화자를 확인하고 발급된 생성 기록을 쓴다. 특정 개인의 유료 목소리·계정을 강제하지 않는다.
- 음성을 장면마다 만들고 실제 파일 SHA와 생성 출처를 기록한다. 무음·누락·오독·태그 낭독을 검사한다. 재생 속도를 바꿔 시간을 맞추지 않고 실제 음성 길이 뒤에 실습용 정지 시간을 더한다.
- 동봉 `scripts/render_lesson.py`를 재사용한다. 매 강의마다 새 렌더러를 만들지 않는다. `--frames` → 실제 최종 화면 검수 및 `preview_review` 기록 → `--validate` → 최종 렌더 순서다. `preview.json`의 정확한 PNG 해시를 장면에 기록하며 레이아웃·문구·마킹이 바뀌면 다시 확인한다. 기존 출력은 덮어쓰지 않는다.
- 기본 도구는 장면별 정지 캡처·강조·음성·요약 카드와 별도 전체 발화 SRT를 만든다. 연속 화면 녹화 편집이나 정교한 움직임이 핵심이면 사용자에게 Remotion 스킬을 제안한다. 사용자가 이 방식을 지정했다면 임의로 바꾸지 않는다.

## 검증과 전달

[references/quality.md](references/quality.md)에 따라 파일 디코드·해상도·음성·자막 범위와 시작·중간·끝 재생을 확인한다. SRT는 짧은 구절로 나누고, 승인된 전체 대본과 누락 없이 대조한다. 기본 구절 시각은 장면 음성 안의 추정치이며 단어별 정밀 정렬이 아니다. 실제 시각을 확인했다면 장면의 `subtitles`에 넣는다. 전사·강제 정렬 도구가 있으면 보정하고 없으면 그 한계를 기록한다. 자동 검사·AI 화면 검토·사람의 전편 청취를 구분한다.

MP4, SRT, 대본, lesson.json과 캡처/음성 원본, 렌더 영수증을 전달한다. 기본 완료 범위는 로컬 제작이다. 제품 업로드·공개 공유·기존 강의 교체는 별도 요청 범위에서만 한다. 오류가 나면 [references/first-run.md](references/first-run.md)를 읽고 해당 원인만 수정한다.
