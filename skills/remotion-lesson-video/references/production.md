# 프로젝트 구성과 렌더

[English](production.en.md) · 한국어 · [日本語](production.ja.md)

## 실행 환경

터미널, Node.js, 패키지 관리자, 브라우저 렌더 실행 가능 여부를 확인한다. 운영체제·Node 지원 범위는 [설치 문서](https://www.remotion.dev/docs/)에서 현재 기준을 확인한다. 기존 프로젝트의 lockfile과 모든 `remotion` / `@remotion/*` 패키지 버전을 확인하고 호환되는 동일 버전으로 유지한다. 임의로 전역 설치하거나 기존 프로젝트를 최신 버전으로 올리지 않는다.

신규 프로젝트는 공식 생성기로 만든다. 예를 들어 현재 공식 안내의 `npx create-video@latest`를 사용하되 호스트의 실행·네트워크 정책을 따른다. 생성 위치는 사용자가 작업할 수 있는 새 폴더로 정한다. 생성기 질문과 기존 파일을 살펴보고 교육영상에 필요한 최소 구성을 선택한다.

[Remotion 공식 스킬](https://www.remotion.dev/docs/ai/skills)이 설치되어 있으면 코드 작성에 활용할 수 있다. 이 스킬은 교육 구성과 실제 화면 제작 절차를 담당하며 공식 스킬 설치를 필수 조건으로 삼지 않는다.

## 프로젝트 구조 예시

```text
lesson-project/
  src/               Composition, 장면, 자막·확대 구성
  public/media/      실제 녹화, 음성, 사용 허가된 시각 자료
  content/           학습 목표, 대본, 타임라인, 출처
  output/            최종 MP4와 SRT
  qa/                파일 해시, 기술 검사, 재생 확인 기록
```

사용자 원본은 보존한다. 녹화별로 대상 화면, 촬영일, 언어, 실제 수행 동작, 사용 구간을 기록한다. 업로드된 자료의 임시 서명 URL·인증값은 소스에 넣지 않는다.

타임라인에는 장면 ID, 원본 녹화 구간, 시작/끝 프레임, 음성 파일, 발화·자막 시점, 확대 구간, 실습 대기 구간을 기록한다. 시간 단위와 fps를 명시하고 녹화/음성을 자르는 시작점의 차이를 반영한다. 사용자 음성을 겹쳐 재생하거나 페이지 끝에서 잘라 버리지 않는다.

## 실행

프로젝트에 정의된 스크립트를 우선 사용한다. 새 프로젝트의 일반적인 실행 형태는 다음과 같으며 `src/index.ts`, `Lesson` 등은 실제 진입점과 Composition ID로 바꾼다.

```bash
npx remotion studio src/index.ts
npx remotion render src/index.ts Lesson output/lesson.mp4
```

명령 인자와 영상·오디오 컴포넌트는 [현재 공식 문서](https://www.remotion.dev/docs/)로 확인한다. 처음에는 실제 콘텐츠가 담긴 짧은 구간을 렌더해 가독성과 타이밍을 점검한 뒤 전체를 렌더한다. 실제 녹화가 없는데 동작을 꾸며서 전체 렌더를 진행하지 않는다.

렌더 오류는 로그의 원인부터 좁힌다. CPU/메모리 압박이면 동시 실행 수를 낮추고, 캐시 권한 오류면 프로젝트의 쓰기 가능한 캐시 경로나 해당 빌드의 캐시 비활성화를 검토한다. 권한 변경·샌드박스 해제를 기본 해결책으로 삼지 않는다.

완료 기록에는 사용한 패키지 버전, 설치/렌더 명령, 입력 자산과 출력 경로를 남긴다. 다른 사용자는 자신의 미디어와 음성으로 교체할 수 있어야 한다.
