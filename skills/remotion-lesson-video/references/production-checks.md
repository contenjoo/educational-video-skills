# 시행착오 재발을 줄이는 제작 기준

[English](production-checks.en.md) · 한국어

실제 제작·대화에서 드러난 오류를 작업 판단과 검증으로 옮긴 기준이다. 개인 계정·화자·파일 위치·기존 강의 원본은 필요하지 않다.

| 과거 문제 | 이번 작업에서 적용할 기준 | 자동 검사의 한계 |
| --- | --- | --- |
| 기존 제작 방식을 잘못 이해해 다른 스킬 제작 | 사용자가 기존 프로젝트를 지칭하면 실제 README·현재 입력·렌더 명령을 확인하고 방법과 산출물을 한 문장으로 정한다. 제품 이름만으로 편집 방법을 추정하지 않는다. | 적절한 제작 방식은 요청과 실제 자료로 판단한다. |
| 쉬운 시범만 보고 대량 제작·시간을 낙관 | 짧은 완성본과 메뉴 이동·권한·여러 클릭이 있는 대표 장면을 먼저 끝낸다. 이미 승인된 일괄 작업은 이 결과로 필요한 수정 후 계속한다. | 1편의 렌더 시간은 전체 촬영·음성·검수·게시 시간의 추정치가 아니다. |
| 번호를 지운 자리의 빈칸, 클릭 후 사라진 대상, 옆에 표시된 네모 | 깨끗한 원본과 강조를 분리한다. 클릭 전 상태와 결과를 보존하고, 설명 시점의 실제 버튼에만 숫자 없는 네모를 둔다. 번호 제거 후 카드와 여백도 다시 배치한다. | 크롭·좌표 범위와 미리보기 SHA는 검사할 수 있지만, 네모가 의미상 맞는 버튼인지는 화면을 직접 봐야 한다. |
| 세로 크롭이 메뉴를 숨기거나 표시·설명이 겹침 | 실제 출력 크기로 모든 고유 표시 상태와 전환 전후를 확인한다. 확대와 개인정보 가림이 필요한 메뉴·설명을 가리지 않게 한다. | 몇 장의 contact sheet만으로 모든 상태를 확인했다고 쓰지 않는다. |
| 영상은 번역했지만 문서·폴더·화면 언어가 남음 | 영상·SRT·표시/발음 대본·문서·폴더·메뉴명을 하나의 언어별 납품 단위로 정한다. | 폰트 경로가 맞아도 글리프·줄바꿈·아랍어 등 RTL 조형/읽기 방향이 맞는 것은 아니다. 실제 프레임에서 확인한다. |
| 원본 음성을 보존했지만 원래 있던 음성 오류를 놓침 | 짧은 음성을 실제로 확인하고, 원본뿐 아니라 최종 MP4의 누락·반복·끊김·무음·발음도 검사한다. 긴 생성이 불안정하면 검증 가능한 장면/묶음으로 나눈다. 실패 시 기존 생성 결과를 확인한 뒤 해당 부분만 재시도한다. | 음성 해시 일치·파형/전사 대조·음량은 자연스러운 발음이나 전체 청취 승인이 아니다. |
| 말 중간에 임의 쉼 삽입, 자막 한 구절이 0초가 되어 사라짐 | 발화를 자르거나 속도를 바꿔 시간을 맞추지 않는다. 측정한 실제 무음이나 문장 끝에만 필요한 쉼을 넣는다. 승인된 전체 표시 대본과 최종 SRT의 문구·시간을 대조한다. | 자동 자막 시간 추정은 강제 정렬이 아니다. 생성된 모든 구절이 남았는지와 실제 재생을 따로 확인한다. |
| 과정명·차시 수·다음 차시 안내 오류 | 확정 목차 한 곳에서 표지·소개·정리·다음 차시를 가져오고 현재 화면과 음성의 의미를 대조한다. | 기술적으로 정상인 파일에도 잘못된 설명이 있을 수 있다. |
| 한글 이름 비교 오류·FFmpeg가 배치 입력을 소비 | 파일명 비교는 NFC로 정규화하되 원본 이름은 보존한다. FFmpeg 반복 실행에는 -nostdin, subprocess에는 DEVNULL을 쓴다. | 이름 일치만으로 파일 내용·업로드·재생을 확인할 수 없다. |
| 인증·모델·네트워크·가상환경을 스킬 실패와 혼동 | 모델 호출, 로그인 계정, Python/Pillow 환경, npm 연결, 음성 생성, 렌더 중 실패 지점을 구분한다. 정상 승인 경로를 사용하고 전역·보안 설정을 임의 변경하지 않는다. | 공급자가 성공 코드를 반환해도 실제 미디어가 비었을 수 있다. |
| 로컬 수정·업로드와 실제 학습자 공개본을 혼동 | 요청된 각 목적지별로 기존 파일 ID·URL·학습진도를 보존하고 교체 여부를 다시 읽는다. 개별 강의·통합 사이트·Drive·모바일은 필요한 범위에서 별도로 재생한다. 새 공개본을 확인하고 승인 범위 안에서만 구본을 정리한다. | 서버 재인코딩본은 로컬 해시와 다를 수 있다. 로컬 SHA와 목적지 자산/버전·길이·수정 장면을 함께 기록한다. |
| 검증 서류·반복 확인이 제작보다 오래 걸림 | 기존 입력·렌더 영수증·검수 기록에 필요한 정보만 보탠다. 공통 도구를 재사용하고, 관련 파일이 바뀌거나 문제가 생긴 검사만 다시 한다. | 별도 차시 스크립트·중복 검수 파일·불필요한 교차 승인 절차를 늘리지 않는다. |

## 완성 파일 검사

동봉 `scripts/check_media.py`는 두 스킬 어디서나 독립 실행된다. Python 표준 라이브러리와 FFmpeg/FFprobe가 필요하다.

```bash
python3 "$SKILL_DIR/scripts/check_media.py" output/lesson.mp4 --srt output/lesson.srt --expected-text output/narration.txt --output qa/media.json
```

`--expected-text`는 제목·차시 번호·시각·마크다운이 없는 **승인된 전체 표시용 발화 대본**이다. 발음용 대본과 다르면 자막에 쓸 표기를 지정한다. 기존 대본에 제목이 있으면 텍스트 본문만 추출한다. 캡처 렌더러는 이 파일을 자동 생성하고 같은 검사를 렌더 중 실행하므로 변경이 없다면 다시 실행하지 않는다. Remotion에는 기존 프로젝트의 내보낸 MP4·SRT와 대본을 넘긴다.

전체 디코드, 영상·음성 스트림, 유효 길이, 사실상 빈 음성, SRT 누락·반복·겹침·0초·범위 초과를 검사한다. 긴 자막 줄/표시 시간은 언어·배치에 맞게 확인할 **경고**이며 `--max-line-chars`로 줄 길이 기준을 조정한다. 기술 검사 통과 상태도 `technical_checks_passed_pending_review`다. 실제 발음·화면과 설명의 의미 일치·사람의 전편 청취·게시본 확인은 자동 통과로 쓰지 않는다.

## 결과 보고

한 번의 완료 보고에 사용한 원본과 제공받은 중간 자료, 실제 명령, 최종 파일 SHA, 수행한 검사와 경고, 직접 확인한 재생 구간, 미확인 항목, 목적지별 반영 상태를 묶는다. 로컬 렌더·업로드·목적지 교체·공개본 재생은 각각 확인된 범위만 말한다. 보조 실행으로 완성한 것을 독립 전체 성공으로 쓰지 않는다. 촬영·음성·렌더·검수·게시의 시간과 외부 대기를 구분하고 불확실한 예상을 보장하지 않는다.

실패 보고는 사용자 보고·로컬 재현·수정 기록·실제 공개본 반영 확인을 구분한다. 실제 로그·파일을 대조한 뒤 원인을 말한다. 미해결 경고가 남으면 최종 검수 완료라고 쓰지 않으며, 검토 후 허용한 경고는 이유를 기록한다.
