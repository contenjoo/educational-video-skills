# 初回実行と復旧

[한국어](first-run.md) · [English](first-run.en.md) · 日本語

1. ホストがスキルを検出・読み込みできることを確認し、新規フォルダーで短い授業を作る。既存の講座を保全する。
2. 元素材の長さ、映像ストリーム、実操作を確認する。不足素材を捏造せず必要な録画を依頼する。
3. 必要なツールと通信をレンダリング前に確認し、利用不能な導入を繰り返さない。
4. 音声付き授業では一文を試し、音声ストリーム、実際の長さ、音量を確認する。ファイルの存在だけで音声生成成功としない。
5. 実素材と依頼された字幕・音声を含む短い区間を先にレンダリングする。

| 症状 | 復旧 |
| --- | --- |
| ログイン済みでも推論中にOAuth期限切れ | 通常のログイン・更新後、実際のモデル呼び出しを確認する。トークンを抽出・公開しない |
| 設定モデルがアカウント非対応 | 今回の実行で対応モデルを選び、全体設定を上書きしない |
| レジストリーのDNS・通信エラー | DNS、プロキシ、ホスト規則を切り分け、通常の承認を使う。保護を解除しない |
| macOS sayが拒否される・約4KBの空ファイル | FFprobeで長さを確認し、許可された実行、提供音声、利用可能なTTSを使う |
| 状態フォルダーが読み取り専用・app-server権限エラー | 必要な書き込み先を確認し、認証・設定のコピーで回避しない |
| 韓国語のキー入力が空白になる | 対応するUTF-8入力を使い、保存結果を読み返す。同じキー操作を繰り返さない |

有用な途中台本・ソース・無音プレビューは保全し、音声やRemotionレンダリングの未完了を明示する。別方式のMP4をRemotionの成功と扱わない。

## ブラウザーURLの確認中に録画が止まる場合

- ウィンドウのタイトルが読めても現在のURLの検証完了ではない。`capture blocked before start / Remotion render not attempted` と報告し、Remotion自体が利用不能とは断定しない。診断ログがなければ内部原因は不明とする。
- ツールのURL信頼確認と保護を維持する。同じエラーが続いたら自動録画を止める。根拠なくウィンドウ再表示、タブを一つにする操作、アプリ更新を繰り返し依頼しない。診断上意味のある変化がある場合に再試行する。
- 提供された録画は長さ、映像ストリーム、必要な実操作、個人情報を確認し、ブラウザーを操作せずローカル編集できる。Chromeや録画元のサイトを開き続ける必要はない。録画がなければ必要な短い操作録画を依頼し、入手までは撮影を未完了とする。
- 無音・字幕付き動画という明示依頼ではTTSや音声を必須にしない。Remotion出力は `python scripts/check_media.py lesson.mp4 --silent --srt lesson.srt --expected-text captions.txt` で検査し、captions.txtには承認済み表示台本の全文を入れる。音声付き授業の音声検査を回避するために使わない。キャプチャ用 `render_lesson.py` は音声入力が必要であり、無音制作に対応したと扱わない。
- ホストツールの修復依頼では製品・ツールの版、エラー原文、録画開始の有無を集める。別のコンピューターでの成功は問題のWindows環境の復旧証明ではない。
